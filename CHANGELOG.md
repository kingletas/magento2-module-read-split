# Changelog

All notable changes to this module are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 1.0.0 - 2026-10-06

First release. Requires PHP 8.3 or later. Read-after-write across requests needs MariaDB with GTID replication; the README says what the module does without it.

### Added

- Sends a storefront's plain `SELECT`s to a database replica, deciding one statement at a time, and keeps every write, every locking or connection-bound read, and every read after the request's first write on the primary. Only storefront and GraphQL `GET` and `HEAD` requests use the replica; a `POST`, the admin, REST, cron and the command line do not.
- Switched on by a `db/read_split` block in `env.php`, beside the connections, which splits the default connection. Without one, or with `enabled` set to `false`, the store runs Magento's own adapter from the same config, so installing the module changes nothing until it is configured. The block never sits inside a connection, where setup's own adapter would read it and fail.
- The replica connection opens at the first statement that may go there, runs the same connection setup as the primary, and replays the allow-listed session `SET`s in order: `NAMES`, `sql_mode`, `time_zone`, `character_set_*`, `collation_*` and user variables given a plain value. Any other `SET` pins the request to the primary, a user variable set from a function, a subquery, a comparison or a server variable included.
- A connect or query error on the replica sends that statement, and the rest of the request, to the primary.
- A 30-second breaker per web node, kept in marker files under `var/` rather than in the cache, or, when `var/` cannot be written, in a directory under the system temp directory that only the store's own user can write; a marker anywhere another account could have put it is not believed, and neither is one dated in the future. The markers are named by a hash of the installation's root and the replica's host and port, so two stores on one node never share one. A refused connection, a failure while opening the replica, a session `SET` the open replica fails, or a statement the replica fails and the primary answers opens it, and while it is open no request on that node tries the replica. A statement the replica stops for running past `max_statement_time` does not open it: that request reads from the primary from there on, and a warning says so at most once an hour per node. Nor does a statement the replica refuses as wrong for it, SQLSTATE class 42, when the primary answers it: the same fallback, with a warning at most once an hour that carries the server's own words only where they name an object or a grant, and its error number and SQLSTATE otherwise. After 30 seconds one request retries, or under load a few. One warning when it opens and one notice when it closes, never one per request.
- Replication health: about once every 30 seconds per node, and on every retry of an open breaker, the replica is asked `SHOW REPLICA STATUS`, and a stopped I/O or SQL thread, lag over the new `max_lag` setting (30 seconds by default), or a question it cannot answer opens the same breaker. A node with nowhere to keep a marker asks on every request. The replica user needs `SLAVE MONITOR` on MariaDB 10.5 and later.
- `SHOW`, `DESCRIBE`, `DESC` and `EXPLAIN` go to the primary without pinning the request, so a cold cache does not switch the offload off.
- Reads of `session`, every `quote*` table, `quote_id_mask`, every `sales_order*` table, `customer_entity`, `customer_visitor`, `oauth_token`, `jwt_auth_revoked`, `persistent_session`, `login_as_customer` and every `downloadable_link_purchased*` table, and of any table or `name*` pattern in `primary_only_tables`, always go to the primary without pinning the request.
- A read of any `quote*` table also sends the rest of its request to the primary, so a cart is never totalled from the primary's rows and a lagging replica's prices and stock.
- A write over REST sets the position cookie too when it is a `POST`, a `PUT` or a `DELETE`, so the page after an order placed through REST reads the order from the primary until the replica has it. REST reads stay on the primary.
- `position_lifetime` defaults to `max_lag` plus the 30 seconds between replication checks, and is never shorter: a shorter value is raised to it, with a warning at most once an hour per node.
- A `read_timeout` setting (5 seconds by default, 2 at the least) for the replica, applied through `mysqlnd.net_read_timeout` only while the replica connection opens, so a stalled replica costs one request per 30-second window instead of hanging every request. The replica connection is never reopened after it fails within a request, and `max_statement_time` stops a slow replica query a second before the timeout.
- Read-after-write across requests by GTID: a request that wrote, and whose response a cache could not store, sets an encrypted, `HttpOnly`, `Secure`, `SameSite=Lax` cookie holding the primary's position, and the visitor's next request uses the replica only once `MASTER_GTID_WAIT` says it has caught up. A forged or malformed cookie sends that request to the primary and nothing else.
- `pooled: true`, for a replica host that may move statements between backends: the GTID check is skipped, and a visitor with a pending position reads from the primary until it expires.
- The block is matched to its connection by server and database (host, port and database name, with the default port filled in), never by comparing the whole config, which Magento extends before its adapter sees it. A block with no replica host, a replica with no database name, or a `connection` other than `default` is refused when the settings are read, with the reason; every read then goes to the primary, the replica and its breaker are never touched, and a warning is logged at most once an hour per node.
- A setting of the wrong kind, an unknown key, or a table name that is not one is refused by name and never read as a default, which sends every read to the primary and fails the deploy check. A replica password of the wrong kind is refused without being shown. The kill switch is read first, and works whatever else in the block is wrong.
- A request is pinned as a whole: once any split connection of it has written, every split connection of it reads from the primary.
- `bin/magento kingletas:read-split:status`, the deploy check: whether the split is active, the replica it resolved without its password, the settings it resolved, the breaker's state (or, when the web server may keep its markers where the user running the command does not look, that it is unknown from there), and the reason when a configured block is not in use, in which case it exits non-zero.
- Requires PHP 8.3 or later; the suites and the syntax check run on 8.3 and 8.4.
- The package carries a store proof, `packaging/store-proof.sh`, which asserts against a running store with a replica that a storefront request's plain reads go to the replica, that its reads after its first write stay on the primary and see the write, that an installed module with no block changes nothing, and that a replica which does not answer leaves every read answered by the primary with the breaker open.
